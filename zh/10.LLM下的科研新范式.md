# LLM 下的科研新范式

大语言模型正在深刻改变计算机科学的研究方式。前面的章节中多次提到了 LLM 在文献检索、论文写作、代码调试等环节的辅助作用，但这些仍停留在用工具提升效率的层面。当科研全流程都被加速之后，全新的范式也正在浮现——研究者不再亲自执行每一个实验，而是编写研究方向，让 AI Agent 自主迭代，在审查结果后给出方向性指导。

这也意味着科研竞争会更加激烈。Human-on-the-Loop 新范式可能会让科研入门”看起来”更加容易，但我希望大家在拥抱大模型的同时，永远不要让机器代替你来思考。读论文、补充技术知识，这些传统的科研素养训练起码可以让你建立属于自己的科研体系。如果所有的一切都由大模型代劳，尤其是对于科研新手来说，即使取得了不错的实验结果，真正属于你的能力提升却很有限。这也是为什么最近“AI 养知识库”火了——大家在深度 vibe coding 的同时，也开始焦虑自己的核心竞争力和知识体系。毕竟工具只是工具，你的未来还是要靠自己发挥主观能动性。

LLM 的发展很快，对科研的影响也在日益加深，可以说已经渗透进了工作和生活的每个环节。也正因如此，本章的内容或许在几个月后就已经过时了，因此这里不会介绍太多具体的工具使用和操作，希望大家自主探索最新的大模型和编程工具。以下内容更多是围绕 Human-on-the-Loop 新范式展开。

## 从 autoresearch 说起

2025 年 3 月，Andrej Karpathy 发布了 [autoresearch](https://github.com/karpathy/autoresearch)（GitHub 70k+ stars），这个仅约 630 行代码的项目让整个研究社区为之震动。它的核心思想极其简洁：

> Agent 修改 `train.py` → 训练 5 分钟 → 检查验证集指标是否提升 → 保留或回退 → 循环迭代

以每小时约 12 次实验的节奏，Karpathy 让 Agent 通宵自主运行，2 天内完成了约 700 次实验，发现了 20 个有效优化，将训练速度提升了 11%。Shopify CEO Tobias Lütke 随即将同样的方法应用到公司的模板引擎上，通过 37 次自动实验和 93 次自动提交，渲染性能提升了 53%。

这个工作流后来被分析师 Janakiram MSV 总结为 **"Karpathy Loop"**，其核心三要素是：

1. Agent 能够访问和修改的代码文件
2. 单一的、可客观测量的优化指标
3. 每次实验的固定时间预算

autoresearch 真正的洞察不在于自动化本身，而在于重新定义了研究者的角色。项目的文件结构只有三个核心组件：

- `program.md`：研究者用自然语言编写的实验指令——定义研究目标、约束条件、评估标准
- `train.py`：Agent 唯一可以修改的文件——模型定义和训练逻辑
- `prepare.py`：数据准备（不可修改的基础设施）

研究者不再手动编写训练代码，而是**用自然语言编程实验过程**。这形成了一条有趣的链路：人类写自然语言描述 → LLM 翻译为 Python 修改 → Python 训练神经网络。Karpathy 的原话是："All LLM frontier labs will do this. It's the final boss battle."

## Human-on-the-Loop

autoresearch 所体现的，本质上是 **Human-on-the-Loop** 的科研新范式——区别于传统的 Human-in-the-Loop（每一步都需人类审批），Human-on-the-Loop 模式下 Agent 在一定范围内自主运行，人类在关键节点介入和重定向。

但同样需要警惕的问题也有不少：

- **验证结果**：Agent 生成的代码可能有微妙的 bug，每一个关键结果都必须由人类验证。
- **理解你的实验**：不要让 Agent 变成黑盒。即使实验是 Agent 帮你跑的，你也必须完全理解实验设计和代码逻辑——审稿人关心的是你对问题的理解深度。
- **记录可复现信息**：记录 Agent 使用的 prompt、代码版本、运行环境，确保可复现性。
- **学术诚信**：遵循目标会议/期刊对 LLM 使用的政策，对论文内容承担全部责任并披露 LLM 使用情况。

## LLM 辅助科研工具箱

除了前面章节介绍的写作工具和编程工具，以下工具也可以了解一下：

**文献发现与综合**：[Elicit](https://elicit.com/)、[Semantic Scholar](https://www.semanticscholar.org/)、[Consensus](https://consensus.app/)、[Research Rabbit](https://www.researchrabbit.ai/)

**Idea 生成与评估**：LLM 可以作为 brainstorming 的伙伴——有效的做法是在充分了解领域的基础上进行结构化探索（描述现有方法局限、让 LLM 提出改进方向）；目前不要妄想直接让 LLM “给我一个能发顶会的 idea”；LLM 得来终觉浅，绝知此事要躬行，读论文、做 Demo 实验验证这些老套路依然是必需的，毕竟 LLM 的科研素养不等于你的科研素养。

**科研编程与调试**：GitHub Copilot、Cursor、Claude Code 等工具可以加速代码编写、辅助调试和帮助理解代码，目前来说第一梯队还是Claude Code 搭配 Claude opus 模型，其次是量大管饱的Codex、GLM，Cladue Code 本身只是工具，可以接入任意模型，此外也可以试试开源的 OpenCode 工具，接入各家厂商会更方便。

## 给硕博生的建议

1. **工具是手段，不是目的。** 论文的核心竞争力来自你对问题的理解和方法的创新，而非工具的使用
2. **先打好基础，再善用工具。** 在科研初期先通过传统方式建立基本功，具备独立判断能力后才能有效利用 LLM 并识别其错误
3. **保持批判性思维。** LLM 可能编造引用、生成错误代码、给出过于乐观的分析，时刻保持验证的习惯
4. **关注领域政策变化。** 各大会议和期刊对 LLM 使用的政策仍在快速演变，投稿前务必查阅最新要求
